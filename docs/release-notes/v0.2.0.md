## New

- **SQL editor permissions.** The SQL tab still runs only read queries by default. **Permissions** in the toolbar lists exactly what runs and lets you also allow data changes, schema changes, transactions, maintenance (`VACUUM`, `ANALYZE`, `REINDEX`), attaching databases, or other PRAGMAs. Your choice is remembered on this computer. A blocked statement names the permission it needs and offers to allow it.
- Scripts run statement by statement and report how many rows changed. If a statement fails, the error says which one and whether earlier statements were applied. A transaction left open when a run ends is rolled back.
- SQLite's own error text, such as `near "FORM": syntax error`, is shown under each error.
- **Export all rows.** The Data tab can export every row matching the filter, not just the current page. The SQL tab exports the full result instead of the first 1000 rows. Exports can be cancelled and report how many rows were written.
- `EXPLAIN` and `VALUES` queries now run.

## Fixed

- **Security:** a comment containing a quote could hide a second statement from the read-only check, so the SQL tab could run `VACUUM INTO` and write a copy of the database to any path. The SQL splitter now follows SQLite's own rules, and read queries also run with `PRAGMA query_only`.
- Editing a BLOB larger than 64 bytes could replace it with its 64-byte preview. Large BLOBs are now read-only in the editor.
- Text starting with `0x`, such as an Ethereum address, was saved as a BLOB. It is now saved as text; only BLOB fields are edited as hex.
- `DATE`, `DATETIME`, and `TIMESTAMP` values were shown, exported, and saved in a Go time format (`… +0000 UTC`). The Data tab, the row editor, and table exports now keep the stored text.
- Numbers are stored using SQLite's type rules; for example, `2.75` is accepted in a `FLOATING POINT` column.
- CSV exports contain full BLOB values instead of a 64-byte preview. A failed export no longer replaces an existing file.
- Switching tables no longer briefly requests the new table with the previous table's sort and filter, and a slow response can no longer replace newer rows.
- Opening or closing a database no longer waits up to 30 seconds for a running query.
- Row counts update after another program changes the database.
- Identifiers containing `;` in brackets or backticks are no longer rejected.

## Other

- Upgrade to React 19, Vite 8, TypeScript 7, and `modernc.org/sqlite` 1.57.
